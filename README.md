# RoomMade_Merge

룸메이드(Roomade) 통합 프로젝트. 서버, DB, Android 앱을 한 폴더로 모은 것이다.

## 폴더 구조

| 폴더 | 내용 |
|---|---|
| `android-app/` | Android Studio 프로젝트 (Kotlin, XML 화면) |
| `backend/` | Node.js + Express + MySQL API 서버. 자세한 내용은 `backend/README.md` |
| `database/` | MySQL 스키마, 시드, 마이그레이션. 자세한 내용은 `database/README.md` |
| `scripts/` | 폰 테스트 스크립트 (`dev-test.ps1`) |

- **방 정보**(두 번째가 아니라 가운데 탭, 방이 없을 때는 "홈"): 방이 있으면 방 이름·소개·내 권한·구성원 목록과 청소당번 설정, 방 나가기(구성원)/방 삭제하기(방장)가 나온다. 방장은 **초대 코드 재생성**(새 코드를 만들면 이전 코드는 쓸 수 없고, 새 코드는 그때 한 번만 보인다)을 할 수 있다. 방이 없으면 방 만들기/방 참가하기를 고른다.
- **청소당번 설정**(시안 "청소당번 설정"): 방 정보 탭의 "청소당번 설정"에서 연다. 방 구성원 누구나 설정할 수 있다.
  - 반복 주기(**매일/매주/격주/매월/한 번만**), 구성원별 담당 구역(직접 입력)·요일(매일이면 요일 칸이 사라짐), 손잡이를 끌어 순번 바꾸기, 줄 추가·삭제. 한 번만 하는 청소는 완료하면 목록에서 빠지고 순환 스위치도 없다.
  - "매주 담당 구역 바꾸기" 스위치를 켜면 청소를 마칠 때마다 담당자가 순번대로 다음 사람으로 넘어간다. (서버 규칙은 `backend/README.md` 참고)
  - 저장하면 캘린더에 청소 일정이 표시된다.
- **청소 현황**(방 정보 탭의 "청소 현황", 캘린더의 청소 항목을 눌러도 열린다): 이번에 할 청소를 예정일 순으로 보여주고(지난 청소는 빨간색), **완료**(한 번에 누르기) / **담당자 바꾸기** / 건너뛰기 / 미루기(날짜 선택) / 이력 보기를 할 수 있다. **예정일보다 이르게 완료를 누르면 "예정일보다 이르게 완료할까요?"를 한 번 더 묻는다**(예정일 당일이거나 지난 뒤에는 묻지 않는다). 완료·건너뛰기·미루기에는 **메모(선택)**를 남길 수 있고 이력에 보인다. **담당자 바꾸기**는 방 구성원 누구나 할 수 있고 "이번 회차만 대신해요"(회차가 끝나면 원래 담당자, 순환이면 원래 담당자 기준으로 돌아간다) 또는 "앞으로 계속 바꿔요"를 고르며 사유(선택)를 남길 수 있다. 바꿀 때마다 **누가·누구에서 누구로·이번만/계속·사유**가 이력에 남고, 청소 항목 수정이나 청소당번 설정에서 담당자를 바꿔도 같은 이력이 남는다. **"전체 청소 이력" 화면**에서 방 전체의 완료·건너뜀·미룸·담당자 변경을 예정일 최근순으로 볼 수 있다(완료 시각은 보여주지 않는다). **미루기는 한 회차에 1번, 예정일에서 최대 7일까지**만 된다(이미 미룬 청소는 목록에 "미룸"으로 표시되고, 완료·건너뛴 다음 회차는 다시 1번 미룰 수 있다). **완료와 건너뛰기는 그 회차의 담당자만** 할 수 있고(방장도 담당자가 아니면 못 한다. 담당자가 없는 청소는 누구나), 담당자가 아니면 "완료" 버튼과 메뉴의 "건너뛰기"가 보이지 않는다. 다른 사람이 대신하려면 "담당자 바꾸기"를 한다. 미루기는 담당자·방장(담당자가 없으면 누구나)만 한다. 순환이 켜져 있으면 완료 뒤 다음 담당자가 안내된다. 다른 사람이 먼저 처리했으면 서버가 거절하고 목록을 새로 고친다.
- **프로필**(시안 Frame 1): 닉네임, 닉네임 아래 "방 이름 · 방장/멤버"(한 계정은 방 하나만 가입), 완료한 청소(내가 직접 완료한 횟수, 서버가 센다)·도움받은 횟수(화면만 있고 지금은 0, 서버 집계 없음), 메뉴(내 정보 / 알림 설정 / 자주 묻는 질문 / 고객센터 / 로그아웃). 알림 설정·자주 묻는 질문·고객센터는 "준비 중".
  - **내 정보**: 이름·닉네임·전화번호 수정, 비밀번호 변경(새 토큰 저장, 다른 기기 로그아웃), 계좌 변경(현재 비밀번호 확인). 계좌는 마지막 4자리만 보인다. 아이디·생년월일·성별은 바꿀 수 없다.
  - 전화번호·계좌·생년월일은 지금처럼 가입 때 필수로 받는다. (재검토는 나중에)
- **캘린더**: 월 달력 + 날짜별 목록. 일정이 있는 날은 점이 찍힌다.
  - 목록에 **공유 일정, 내 개인 일정, 청소 당번 예정일, 물품 유통기한**이 함께 나오고, 종류마다 막대 색이 다르다.
  - 일정 추가·수정·삭제(작성자·방장), 공유/개인 선택, 내용(메모) 입력
  - 청소는 기본으로 당번의 "다음 예정일"에만 표시하고, 설정에서 "반복 청소 날짜 계속 표시"를 켜면 이후 날짜도 보인다. 청소·유통기한 항목은 눌러도 수정되지 않고 안내만 나온다.
- **창고**: **생활용품만** 다룬다. 공유 물품(생활용품)·유통기한 임박·냉장고 음식 숫자, 함께 쓰는 물품 목록(공용 + 내 개인 물품 + **다른 구성원의 개인 물품(읽기 전용)**). 음식(식재료)은 모두 냉장고에서 다룬다.
- **냉장고**: **모든 음식(식재료)**을 여기서 본다. 내 음식 / 공용 음식 / 구성원 음식(다른 구성원의 개인 음식, 읽기 전용) 탭, 유통기한 임박 강조. 음식 추가·QR 입력도 여기서 한다.
- **물품 추가·수정**: 직접 입력, QR 코드로 입력, 공용/내 것 선택, 수량 조정, 공용↔내 것 바꾸기, 삭제
- **초대 코드**(방 정보 탭 오른쪽 위 `Invite` 버튼, 방장만): 팝업 하나로 처리한다. 안내(코드는 만들 때 한 번만 보이고, 새 코드를 만들면 이전 코드는 쓸 수 없다)를 보여주고 "새 코드 만들기"를 누르면 같은 팝업이 새 코드와 복사 버튼으로 바뀐다. 코드는 확인을 눌러야 닫힌다.
- **일정 알림 시간**(일정 추가·수정 > 알림): 시작 몇 분 전에 알릴지 일정마다 정한다. 없음 / 정각 / 10분 / 30분 / 1시간(기본) / 1일 전 중에서 고르거나 직접 입력(분·시간·일, 최대 30일 전). 공유 일정은 방 구성원 모두(작성자 포함)에게, 개인 일정은 작성자에게만 알림이 간다. 알림 시간을 바꾸면 새로 알린다. 기존 일정은 60분 전으로 유지된다.
- **반복 청소 날짜 표시**(프로필 > 설정 > "반복 청소 날짜 계속 표시"): 끄면(기본) 캘린더에 다음 예정일만, 켜면 그 이후 반복 예정일도 보여준다. 순환 당번은 이후 날짜의 담당자를 "당번 순환"으로 표시한다. 이 폰에만 저장된다.
- **자동 로그인**: 로그인할 때 "로그인 유지"를 체크했다면 앱을 다시 켜도 로그인 화면 없이 바로 들어간다(최대 30일). 체크하지 않았거나 토큰이 만료되면 로그인 화면이 나온다.
- **프로필 사진**(프로필 > 사진 영역): 사진 촬영 또는 갤러리 선택 후 원 안에 맞춰 자르면(움직이기·확대) 512px 정사각형으로 서버에 저장된다. 삭제도 가능하다. 프로필과 방 정보의 구성원 목록에 보이고, 설정의 "프로필 사진 공개"를 끄면 같은 방 사람들에게 보이지 않는다(기본은 공개). 서버는 `user_photos` 테이블에 JPEG를 저장하고 로그인한 같은 방 구성원에게만 `GET /api/users/:userId/photo`로 내려준다.
- **약관 동의(회원가입)**: "전체 동의 / (필수) 이용약관 / (필수) 개인정보 수집·이용" 체크가 있고 [보기]로 문서를 읽을 수 있다. **문서를 열어 맨 아래까지 읽어야 체크할 수 있다**(읽지 않고 체크하면 "끝까지 읽어 주세요" 팝업이 뜨고, 문서 화면의 "모두 읽었어요" 버튼은 끝까지 내려야 켜진다). 둘 다 체크해야 가입된다(서버도 `agreeTerms`·`agreePrivacy`가 `true`가 아니면 거절). 동의한 약관 버전(`1.0`)과 시각이 기록된다.
- **개인정보 처리방침**: 로그인 화면 아래 링크, 가입 화면 [보기], 설정에서 연다. 문서는 `E:\Project\룸메이드(RoomMate) 개인정보 처리방침.txt`(초안)이고, 앱은 `android-app/app/src/main/assets/privacy_policy.txt`에서 읽는다(이용약관 `terms.txt`와 같은 형식). 내용을 고치면 두 파일을 같게 맞춘다.
- **회원 탈퇴**(프로필 > 설정 맨 아래 "회원 탈퇴"): 안내를 확인하고 비밀번호를 입력하면 탈퇴된다. 방에 속해 있으면 방 나가기와 같은 규칙이다: 다른 구성원이 있는 방장은 먼저 위임해야 하고, **받을 돈·보낼 돈이 하나라도 남아 있으면 탈퇴할 수 없으며**(정산 화면으로 바로 갈 수 있다), 내가 등록한 공용 물품은 방장에게 넘기거나 삭제를 고른다. 혼자 남은 방장이 탈퇴하면 방이 삭제된다. 탈퇴하면 이름·전화번호·계좌·생년월일·아이디·닉네임과 프로필 사진·알림·기기 토큰이 지워지고(행은 기록용으로만 남음), 함께 쓰던 지출·청소 기록에는 "탈퇴한 회원"으로 보인다. 같은 아이디·전화번호·닉네임으로 다시 가입할 수 있다. 약관 제14조 3항의 "분쟁 대비 최대 2년 보관"은 하지 않고 바로 지운다.
- **공지사항**(프로필 > 설정 > 공지사항): 목록(고정 공지가 맨 위)과 상세. 앱에서는 읽기만 한다. 운영자는 서버 PC에서 `node scripts/notice.js add "제목" "내용" [--pin]` 으로 등록하고, `list`, `edit`, `delete`로 관리한다(자세한 사용법은 `backend/scripts/notice.js` 맨 위 설명).
- **공동 메모**(방 정보 탭 > 공동 메모): 방 구성원 모두가 보는 메모 목록. 누구나 쓸 수 있고, 수정·삭제는 작성자와 방장만 할 수 있다(그 외에는 읽기만). 작성자가 방을 나가도 메모는 남고 나간 사람으로 표시된다.
- **이메일(필수)**: 가입할 때 인증번호로 확인해야 하고, [프로필 > 내 정보 > 이메일 변경]에서 새 이메일을 인증해야 바꿀 수 있다(아래 "보안 작업으로 바뀐 동작" 참고). 탈퇴하면 이메일은 지워진다.
- **자주 묻는 질문**(프로필 > 자주 묻는 질문): 분류별 질문을 눌러 답을 펼쳐 본다. 내용은 `android-app/app/src/main/assets/faq.txt`(복사본 `E:\Project\룸메이드(RoomMate) 자주 묻는 질문.txt`)에서 읽고, `## 분류` / `Q. 질문` / `A. 답변` 형식이라 파일만 고치면 된다. 지금은 앱 기능 기준으로 쓴 초안이다.
- **고객센터**(프로필 > 고객센터): 운영자 문의처가 정해지기 전에 앱 안에서 문의를 받는다. 자주 묻는 질문 보기, 문의하기(제목·내용, 하루 10건까지), 내 문의 목록·상세(답변 대기/답변 완료)가 있다. 운영자는 서버 PC에서 `node scripts/inquiry.js list [--waiting]`, `show <번호>`, `reply <번호> "답변"` 으로 보고 답한다. 답변이 달려도 알림은 가지 않으므로 회원이 고객센터 화면을 열어야 보인다.
- **검색**(하단 검색 탭): 검색어를 입력하면 우리 방의 음식·물품·일정을 한 번에 찾는다(입력을 멈추고 0.3초 뒤 검색). 음식·물품은 이름·보관 장소·등록한 사람, 일정은 제목·내용·작성자, **일정에는 청소도 포함**돼 항목·담당자로 찾는다. 전체/음식/물품/일정 분류와 개수, 결과 카드를 누르면 음식은 냉장고, 물품은 창고 탭, 일정·청소는 캘린더 탭으로 이동한다. 보이는 범위는 각 목록과 같아서 다른 구성원의 개인 일정은 나오지 않고, 개인 음식·물품은 읽기 전용으로 나온다.
- **정산**(프로필 > 정산): 위쪽에 받을 돈·보낼 돈 합계와 사람별 미정산 금액, 아래에 지출 내역(정산 중/정산 완료). 지출을 누르면 분담 내역과 정산 상태를 본다.
  - **지출 등록**(+ 지출 등록): 내용, 금액, 날짜, 함께한 사람. 똑같이 나누기(나누어떨어지지 않는 1원은 앞사람부터 한 명씩 더 냄) 또는 사람마다 금액 직접 정하기(합이 총 금액과 같아야 저장됨).
  - 결제한 사람만 정산 완료 표시(받았어요/취소), 수정, 삭제를 할 수 있다. 정산된 분담이 있으면 금액·분담은 못 고치고 삭제도 못 한다(내용·날짜만 수정 가능).
  - 지출 알림(새 분담금, 정산 완료)을 누르면 정산 화면이 열린다.
- **알림**: 캘린더·창고·방 정보 화면 오른쪽 위의 종(안 읽은 개수 배지)을 누르면 알림 목록이 열린다. 전체/안 읽음 필터, 누르면 읽음 처리 + 해당 탭으로 이동, 길게 누르면 삭제, 모두 읽음, 읽은 알림 삭제, 더 보기.
  - 알림 종류: 유통기한, 청소 당일(오전 9시), 일정 시작 60분 전, **청소 담당 변경**(담당이 된 사람·빠진 사람에게, 바꾼 본인 제외).
  - **진짜 푸시(FCM)**: Firebase 설정을 하면 서버가 알림을 만드는 즉시 폰으로 푸시를 보낸다(앱이 꺼져 있어도). 설정 방법은 아래 `알림 푸시(FCM) 설정` 참고. 설정하지 않으면 아래 15분 확인 방식으로 동작한다.
  - **폰 알림창**: 앱이 꺼져 있어도 15분마다(안드로이드 최소 간격) 서버를 확인해 새 알림을 알림창에 띄운다. 처음 확인할 때는 예전 알림을 띄우지 않고 기준만 잡는다. 로그아웃하면 멈춘다. Android 13 이상에서는 처음에 알림 허용을 묻는다.
  - 한계: 진짜 푸시(FCM)가 아니라서 **즉시 오지 않고(최대 약 15분 지연)**, 서버(PC)에 접속할 수 있어야 한다. 서버를 안 켰거나 폰이 다른 네트워크면 확인되지 않는다. 로그인 유지를 체크하지 않은 계정도 이 확인 때문에 토큰이 계속 갱신된다.
- **팝업(알림창)**: 모든 확인·삭제·입력 팝업이 앱 색에 맞게 통일돼 있다(카드 색 바탕, 둥근 모서리, 제목 진한 갈색, 확인 버튼 주황, 취소 버튼 연한 갈색). 어두운 모드에서도 같은 색 이름으로 바뀐다. 스타일은 `res/values/styles.xml`의 `Rm.MaterialAlertDialog`.
- **안내 메시지**: 시스템 토스트 대신 앱 안 스낵바(**밝은 모드·어두운 모드 모두 흰 바탕에 검은 글씨**, 둥근 모서리)로 보여준다(토스트에는 시스템이 앱 아이콘을 붙이기 때문). 하단 메뉴바 위에 뜨고, 저장하고 화면이 닫히는 경우에는 이전 화면에서 보여준다. 코드는 `util/Msg.kt`.
- **설정**(프로필 오른쪽 위 톱니바퀴): 알림 설정, 화면 모드(기기 설정 따라가기 / 밝게 / 어둡게), 글자 크기(작게·보통·크게·아주 크게), 이용약관, 앱 버전. 화면 모드와 글자 크기는 그 폰에만 저장된다.
- **알림 설정**(설정 또는 프로필 > 알림 설정): 유통기한 / 청소 / 일정 / 지출·정산을 종류별로 **푸시만** 끌 수 있다. 꺼도 앱 안 알림 목록에는 계속 쌓인다. 서버에 저장된다(`GET·PATCH /api/users/me/notification-settings`).
- **방 정보 수정**(방 정보 탭, 방 이름 옆 연필 버튼, 방장만): 방 이름·소개·최대 인원. 최대 인원은 현재 구성원 수보다 작게 줄일 수 없다.
- **프로필 활동 요약**: 완료한 청소(내가 직접 끝낸 횟수)와 도움받은 횟수(내가 "이번 회차만" 넘긴 청소를 다른 사람이 대신 끝낸 횟수)를 서버가 센다.- 색·버튼·카드 모양은 Figma 시안(`E:\Project\UI`)을 따른다. 시안이 없는 화면은 같은 스타일로 직접 만들었다.

### 서버 규칙 중 앱 동작에 영향을 주는 것
- 한 사람은 방 하나에만 가입할 수 있다. 방 정원은 2~10명이고 기본값은 10명이다(방 만들 때 선택).
- 초대 코드는 6자리이고 만들 때 한 번만 보인다.
- **개인 일정은 작성자에게만 보인다.** 다른 구성원과 방장에게는 목록에 나오지 않고, 주소로 직접 접근해도 404이며, 시작 알림도 가지 않는다.
- 서버는 개인 물품도 방 구성원 모두에게 내려준다(소유자 이름 포함). 수정·삭제는 등록한 사람만 할 수 있다. 앱의 창고 목록과 캘린더(유통기한)에는 다른 구성원의 개인 물품도 "개인 · 등록한 사람"으로 보이지만 **읽기 전용**이라, 누르면 내용만 나오고 수정·삭제는 등록한 사람만 할 수 있다. 냉장고에서는 "내 음식" 탭에 내가 등록한 개인 음식, "구성원 음식" 탭에 다른 구성원의 개인 음식이 나온다. (서버에서 숨기는 방식은 검토 후 되돌렸다.)
- QR 상품명 조회(`GET /api/products/lookup`)는 로그인이 필요하고, **GS25 상품 QR(`hpimg.gsretail.com`)만** 지원한다.
  - 다른 호스트, http, 계정 정보·다른 포트가 붙은 주소, 내부 IP는 거절한다. 다른 주소로의 이동은 따라가지 않고, 응답 1MB·8초·분당 20회로 제한한다.

## 시작하기

### 1. DB (MySQL)
`database/schema.sql`을 적용한다. **이미 DB를 만든 팀원은 `database/migrations/` 안의 파일을 날짜 순서대로 한 번씩 실행한다.**

| 파일 | 내용 |
|---|---|
| `2026-11-25_rooms_description.sql` | `rooms.description`(방 소개) 컬럼 추가 |
| `2026-11-26_schedules_description_visibility.sql` | `schedules.description`(내용), `schedules.visibility`(공유/개인) 컬럼 추가 |
| `2026-11-26_cleaning_rotation.sql` | `cleaning_tasks.rotation_enabled` 컬럼, `cleaning_rotation`(청소 순번) 테이블 추가 |
| `2026-11-26_cleaning_reassign.sql` | `cleaning_tasks.base_assignee_user_id`(이번만 대신하는 경우의 원래 담당자) 컬럼, `cleaning_assignee_changes`(담당자 변경 이력) 테이블 추가 |

이 PC는 학교 수업용 MySQL 5.7(3306)과 MySQL 8.0(3307)이 같이 있다. 서버는 `backend/.env`의 `DB_PORT`로 접속한다.

### 2. 서버
```bash
cd backend
npm install
copy .env.example .env   # 값 채우기 (DB 포트·비밀번호, ACCOUNT_ENC_KEY 등)
npm start
```
- 테스트: `npm test` (`roomade_test` DB를 비우고 다시 만든다. 실제 `roomade` DB는 건드리지 않는다.)
- **서버 코드를 고친 뒤에는 서버를 껐다가 다시 켜야 반영된다.**

### 3. 앱
서버 주소는 `android-app/local.properties`의 `roomade.baseUrl`로 정한다. 없으면 에뮬레이터용 `http://10.0.2.2:3000/`.
- 실제 폰: `roomade.baseUrl=http://<PC 내부 IP>:3000/` (폰과 PC가 같은 Wi-Fi여야 한다)
- 값을 바꾸면 다시 빌드한다.

#### Android Studio 없이 폰에서 테스트하기 (`scripts/dev-test.ps1`)
PC 메모리가 부족해서 Android Studio를 켜기 어려울 때 쓴다. 빌드 → 설치 → 실행 → 로그 확인을 한 번에 한다.

```powershell
cd RoomMade_Merge
powershell -ExecutionPolicy Bypass -File .\scripts\dev-test.ps1 -StartServer -ServerIp <PC 내부 IP>
```

- 폰: USB 디버깅을 켜고 PC에 연결한다. Android 15 이상, PC와 같은 공유기.
- 에뮬레이터: `-ServerIp`를 생략한다. (기본값 `10.0.2.2`)
- 코드를 안 고쳤으면 `-SkipBuild`로 설치만 다시 할 수 있다.
- 시스템 환경변수는 바꾸지 않는다. 빌드가 끝나면 Gradle 데몬을 종료해서 메모리를 돌려준다.
- 폰에서 서버에 접속되지 않으면 Windows 방화벽이 3000 포트를 막은 것일 수 있다.
- 서버를 이미 켜 두었으면 `-StartServer`를 빼고 실행한다.

#### 빌드가 jlink 오류로 실패할 때
`gradle/gradle-daemon-jvm.properties`가 JDK 25 데몬을 요구하는데, VS Code의 Gradle 확장이 먼저 띄운 데몬을 재사용하면 `jlink executable ... does not exist`로 실패한다. `dev-test.ps1`은 별도 데몬 폴더(`-Dorg.gradle.daemon.registry.base`)를 써서 피한다. 직접 빌드할 때도 같은 옵션을 준다.

## 알림 푸시(FCM) 설정 (선택)

설정하지 않아도 앱 안 알림 목록과 15분 확인 방식은 동작한다. 즉시 푸시를 쓰려면:

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만들고 안드로이드 앱(패키지명 `com.example.android_project`)을 등록한다.
2. 받은 `google-services.json`을 `android-app/app/` 폴더에 넣고 앱을 다시 빌드한다. (파일이 없으면 푸시 코드는 꺼진 채로 빌드된다.)
3. 프로젝트 설정 > 서비스 계정 > "새 비공개 키 생성"으로 받은 JSON 파일을 서버 PC의 안전한 곳에 두고, `backend/.env`에 `FIREBASE_SERVICE_ACCOUNT=<그 파일 경로>`를 적은 뒤 서버를 다시 켠다. **이 키 파일은 GitHub에 올리지 않는다.**
4. 새 테이블 `device_tokens`가 필요하다: `database/migrations/2026-11-27_device_tokens.sql`을 적용한다.

푸시가 켜진 빌드는 15분 확인을 하지 않는다. (서버에 키가 없으면 푸시가 오지 않으므로 둘을 같이 설정해야 한다.)

### 보안 작업으로 바뀐 동작
- **회원가입**: 이메일이 필수이고, "인증번호 받기 → 6자리 입력 → 확인"으로 본인 주소인지 확인해야 가입된다. 생년월일로 만 14세 미만은 가입할 수 없다. 약관 버전이 1.1로 올라갔다(만 14세 미만 불가, 이메일 등록·인증 조항 추가).
- **이메일 없는 기존 회원**: 로그인하면 "이메일 등록" 화면이 먼저 나오고, 인증해 등록해야 앱을 쓸 수 있다(로그아웃은 가능).
- **내 정보의 이메일**: 바로 고칠 수 없고 [변경]에서 새 이메일을 인증해야 바뀐다. 바뀌면 이전 주소로 알림 메일이 간다. 이메일은 지울 수 없다.
- **비밀번호 찾기**: 로그인 화면의 "비밀번호를 잊으셨나요?"는 바로 "아이디와 이메일로 찾기"로 간다. 가입 정보(이름·전화·생일) 방식과 방법 선택 화면은 없앴다.
- **로그인 잠금**: 같은 아이디로 비밀번호를 5번 틀리면 15분 동안 맞는 비밀번호로도 로그인할 수 없고, 등록된 이메일로 알림이 간다. 잠금 기록은 서버 메모리에 있어 서버를 다시 켜면 풀린다.
- **로그아웃**: 서버가 그 로그인(세션)을 바로 무효화한다. 다른 기기의 로그인은 그대로다.
- **보안 알림 메일**: 비밀번호 변경·재설정, 이메일 변경(이전 주소로), 회원 탈퇴 완료, 로그인 잠금.
- **요청 제한**: 아이디·닉네임 중복확인은 IP당 15분 60회, 이메일 인증번호는 IP당 15분에 보내기 30회·확인 60회와 같은 주소에 60초에 한 번, 로그인한 회원은 1분 120회(`.env`의 `USER_RATE_LIMIT_PER_MINUTE`).
- **개발용 메일 대신 콘솔**: 팀원 PC처럼 메일 설정(SMTP)이 없으면 가입 인증번호를 받을 수 없다. 개발할 때만 `.env`에 `MAIL_DEV_CONSOLE=true`를 넣으면 인증번호가 서버 콘솔에 찍힌다(배포에서는 절대 켜지 않는다).
- **앱 백업**: 로그인 토큰·푸시 기기 정보는 안드로이드 자동 백업과 기기 이전에서 빠진다. 새 폰에서는 다시 로그인한다.

### 백업과 키 보관
- **DB 백업**: `powershell -ExecutionPolicy Bypass -File E:\Project\RoomMade_Merge\scripts\backup-db.ps1` → `E:\Project\backups\db\roomade_날짜.sql`, 최근 7개만 남긴다. 매일 자동으로 하려면 관리자 권한 없이 아래 한 줄로 작업 스케줄러에 등록한다(매일 새벽 3시, PC가 켜져 있어야 한다).
  `schtasks /Create /TN "RoomMade DB 백업" /SC DAILY /ST 03:00 /TR "powershell -ExecutionPolicy Bypass -File E:\Project\RoomMade_Merge\scripts\backup-db.ps1"`
- **복원**: `mysql -h 127.0.0.1 -P <포트> -u root -p roomade < 백업파일.sql`
- **키 보관**: `backend\.env`(JWT·계좌 암호화 키, 메일 앱 비밀번호, DB 비밀번호)와 Firebase 서비스 계정 키(`E:\roommade-...json`)는 Git과 압축 백업에 들어가지 않는다. 비밀번호 관리 도구나 암호를 건 USB처럼 **이 PC 밖 안전한 곳에 따로 한 부** 보관한다. 특히 `ACCOUNT_ENC_KEY`를 잃으면 저장된 계좌 정보를 복구할 수 없다.

## 알려진 사항
- 앱 안에서 방 관련 파일 일부가 `ui/` 폴더에 있지만 패키지는 `ui.room`이다. 동작에는 영향이 없다.
- `Roomade-main` 폴더(친구의 QR 스캔 원본)는 참고용으로 남겨 두었다. 서버 쪽은 로그인 없이 호출되는 코드라서 가져오지 않고, `backend`에 로그인과 제한을 붙여 새로 만들었다.
- 폰 화면으로 아직 확인하지 못한 것: 어두운 모드 전체 화면, 글자 크기 "아주 크게", 팝업·스낵바 모양과 위치, 검색 탭, 자주 묻는 질문, 고객센터, 회원 탈퇴, 공지사항, 공동 메모, 방 정보 수정 화면, 알림 설정 화면, 담당자 변경 푸시, 정산 화면(목록·등록·상세·정산 완료). 폰에서 한 번씩 눌러 보고 어색한 곳을 고쳐야 한다.
- 날짜 선택 창은 안드로이드 기본 모양 그대로다.
